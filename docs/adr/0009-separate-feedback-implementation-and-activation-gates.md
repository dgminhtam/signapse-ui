# Separate feedback implementation and activation gates

The captured backend clarification may guide feedback implementation when the live OpenAPI is intentionally sparse. Fixture contract approval, production activation, and OpenSpec archive remain behind a live dev OpenAPI/API mapping structural cross-check, but BE-explained omissions such as requiredness, nullability, constraints, examples, and lifecycle prose do not block completion. A hard contradiction in paths, methods, authorization scopes, transport fields, response shapes, or statuses still blocks completion. This scoped two-gate model lets frontend and backend documentation proceed in parallel without allowing incompatible contracts through.
